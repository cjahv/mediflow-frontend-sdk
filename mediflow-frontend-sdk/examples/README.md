# 无人值守屏幕示例

`screen.ts` 是浏览器入口，直接创建 `ScreenClient`，页面加载即连接，不要求点击启动、翻历史或手动鉴权。业务项目将导入改为 `@cjahv/mediflow-screen-sdk`，由受保护的配置提供 `screenConfig.baseURL` 和 `screenConfig.token`，不把 token 放入 URL。

页面只需 `#screen`（队列画面）、`#connection`（连接状态）及 `#diagnostic`（受保护的运维状态区）三个元素。配置必须先于入口加载。

## 数据怎么拿、怎么用

- `onSnapshot(snapshot)` 收到当前屏幕的完整状态，不是叫号历史。首次连接、后续有效更新、断线重连后都会通过它交付数据。
- `snapshot.data.queues` 是该屏幕当前队列，`queue.sections` 是队列分区，`section.persons` 是人员。示例直接遍历并渲染名称、姓名和显示编号；不自行移动人员或推导叫号业务。
- 每次整体替换画面；空队列或空分区也按新数据展示，不能保留旧人员。SDK忽略同连接旧版本，重连以服务器首份完整快照为准。
- `client.snapshot` 可读取最后一份快照的独立副本，首次就绪前是 `undefined`。断线时保留最后画面并标记离线，不把旧画面当作最新状态。
- `playback.play` 只提供设备音频能力。SDK自动获取待消费额度、排队、消费及上报日志，不用历史记录驱动播报，也不需要示例自行封装队列。

## 无人值守运行与故障

`connecting` 是连接中；`online` 表示已取得当前快照；`offline` 会自动重连；`rejected` 是配置/权限拒绝，需远程运维修正；`closed` 表示主动停止。`start()` 首次等待超时不停止自动重连。

播放的 `idle/playing/offline/uncertain/paused/closed` 分别表示空闲、播放中、离线、消费结果不确定、暂停、已停止。SDK会自动重试超时的待消费同步；不确定消费在线时按退避间隔以原ID重试，重连后也会恢复并补报日志。设备播放失败或日志缓冲满时会暂停音频并报告错误，不重播失败的那次；队列画面仍可继续更新。远程运维确认恢复后可调用 SDK 的 `resumePlayback()`，`retryConsumption()` 可提前触发一次在线未决消费重试（通常无需调用），日志补报用 `retryPlaybackReports()`。本示例不提供候诊现场操作按钮，也不声称所有设备故障都能自动恢复。

无人值守终端须预先配置音频权限。浏览器禁止自动播放时不能靠 SDK 绕过，应使用允许自动播放的 kiosk 配置或终端原生播放器。播放器声音结束才 resolve，失败则 reject；实际设备应设置播放超时和中止策略。`close()` 停止后续操作，不中止应用自定义的正在播放音频。

队列和未确认日志仅保存在当前 SDK 实例，默认各最多1000条；断电/刷新不保证恢复音频状态，遵循允许故障漏播的约定。历史查询是审计/排查用途，不是此无人值守屏幕示例的一部分。

## 验证

`npm test` 包含 SDK 状态机、示例编译及直接运行入口测试，检查自动启动、当前队列更新、空数据清除和关闭处理；SDK测试另覆盖断线重连后的权威快照及自动播报。
